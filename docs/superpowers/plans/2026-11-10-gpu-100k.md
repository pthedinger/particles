# GPU 100k Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Interactive 100,000-particle GPU sand art, validated on the local M4 Pro.
**Architecture:** GPU ping-pong state, exact-count spatial bins, Jacobi fluid/contact passes, offscreen instanced rendering shared with existing egui controls.
**Tech Stack:** Rust, existing Bevy 0.14.2/wgpu 0.20.1, WGSL, bytemuck.
**Spec:** docs/superpowers/specs/2026-11-10-gpu-100k-design.md

## Global Constraints
- Keep existing CPU mode, tests and user-owned working-tree changes.
- No routine GPU particle readback; small control uploads only.
- 100,000 particles, truthful wall-clock/simulation-time reporting.
- Preserve unilateral grain contacts and approximate immersed-grain coupling.

## Review Focus
- Crowded/edge grid cells must not lose particles or miss neighbours.
- Reset/remix/budget changes while paused must show new state without stale GPU resources.
- Live material edits must reach physics and rendering without resetting positions.
- GPU completion must precede texture consumption; reports must validate GPU rather than CPU seed state.
- Small grains must not cause resolution-dependent slowdown hidden behind displayed FPS.
