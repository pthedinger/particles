# GPU sand art: 100,000 particles

Implement the GPU approach accepted in chat, starting with 100,000 particles. Keep Rust/Bevy 0.14.2, existing recipe controls, circular vessel, rotation, shaking, pause, reset and remix. Retain the CPU solver as an explicit reference mode. No million-particle claim or automatic reduction of simulation speed.

## Approaches
CPU tuning cannot deliver the desired increase. Native Metal would add a platform-specific implementation. Chosen: WGSL compute through Bevy's existing wgpu/Metal device, with GPU drawing into a texture shared with egui. This keeps the UI and supports other wgpu backends.

## Architecture
The GPU owns two particle buffers; invocations read an immutable snapshot and gather their own corrections. A uniform grid uses counting, parallel prefix scans and scatter into an exactly N-sized spatially sorted particle buffer, avoiding fixed per-cell capacity and lost particles. Rebuild between pressure/contact iterations. Pressure multipliers and corrections use separate dispatches. A conservative swept guard prevents fast pairs crossing between prediction endpoints, with exact high-speed impact momentum outside this visual model. Grain contacts are unilateral, friction needs normal load, and fluid samples do not act as rigid beads against grains. Gas pressure is separate from liquid projection to prevent collapsed low-mass parcel clusters. Buoyancy/drag preserve the existing approximate immersed-grain model; this remains a visual simulation, not CFD.

A render-world system submits compute and offscreen instanced drawing before egui consumes the texture. CPU sends only small controls/material updates and initial/reset seeds. Readback is confined to explicit tests/reporting, never ordinary frames. Preserve deterministic seeding, not bitwise GPU trajectories (atomic bin insertion order can vary).

## Builder decisions
Use exact-count bins with 256-lane scans with 512 block entries, six pressure/contact iterations after regression-driven convergence/performance tuning, 1/120 s substeps and a 1024-square render target. Timesteps, pressure stabilization and iteration count may change on measured stability/performance evidence. Keep changes on existing codex/particle-sand-art branch and preserve the pre-existing Cargo.lock changes, a.out and tmp.c.
